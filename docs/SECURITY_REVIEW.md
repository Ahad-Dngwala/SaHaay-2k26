## SR-01 — CRITICAL: HTTP-Only Transport (No TLS)

**Finding:** All server communication (REST API, WebSocket) runs over plain HTTP on port 3000.  
**Risk:** Credential interception, session token hijacking, mission data eavesdropping on any non-loopback network.  
**Affected paths:** All `/api/*` endpoints, WebSocket `/ws`.

**Remediation (production):**

```bash
# Option A — Reverse-proxy with Nginx + Certbot (recommended)
sudo apt install nginx certbot python3-certbot-nginx
certbot --nginx -d dispatch.sahaay.gov.in

# Option B — Node.js native HTTPS
import https from 'https';
import fs from 'fs';
const server = https.createServer({
  key: fs.readFileSync('key.pem'),
  cert: fs.readFileSync('cert.pem'),
}, app);
```

## SR-02 — CRITICAL: Development Keystore Committed to Repository

**Finding:** `artifacts/sahaay-release-key.jks` is committed to the git history.  
**Alias:** `sahaay-release`  
**Risk:** Anyone with repo access can sign malicious APKs that appear legitimate to Android's signature scheme. Users could install a trojaned app that looks like SaHaay.

**Remediation (production):**

1. Generate a new secure keystore **outside** the repository:
   ```powershell
   keytool -genkey -v -keystore ~/secure/sahaay-production.jks `
     -alias sahaay-prod -keyalg RSA -keysize 4096 -validity 10000
   ```
2. Store the keystore in a secrets vault (e.g., Google Secret Manager, GitHub Actions Secrets).
3. Add `*.jks` to `.gitignore`.
4. Rotate APK signing (Play App Signing handles this for Play Store releases).
5. Remove the dev keystore from git history: `git filter-repo --path artifacts/sahaay-release-key.jks --invert-paths`

## SR-03 — CRITICAL: No Rate Limiting on SOS Endpoint

**Finding:** `POST /sos` accepts unlimited requests. No throttle, captcha, or token requirement.  
**Risk:** Trivial DoS — an attacker can flood dispatch with fake emergencies, saturating all available drivers and leaving real patients without coverage.

**Remediation (production):**

```typescript
import rateLimit from 'express-rate-limit';

const sosLimiter = rateLimit({
  windowMs: 60 * 1000,   // 1 minute window
  max: 3,                 // max 3 SOS requests per citizen per minute
  keyGenerator: (req) => req.body?.phone || req.ip,
  message: { error: 'Too many SOS requests. Please call 108 directly.' },
});

router.post('/sos', sosLimiter, sosHandler);
```

## SR-04 — HIGH: No CORS Whitelist

**Finding:** The Express server does not set `Access-Control-Allow-Origin` headers. In development, Vite proxy handles CORS. In production, any origin can call the API.  
**Risk:** Cross-site request forgery on authenticated admin endpoints.

**Remediation:**

```typescript
import cors from 'cors';
app.use(cors({
  origin: ['https://sahaay.gov.in', 'https://admin.sahaay.gov.in'],
  credentials: true,
}));
```

## SR-05 — HIGH: No JWT Refresh / Token Expiry Enforcement

**Finding:** Bearer tokens generated by `server/src/auth.ts` use a simple UUID stored in an in-memory `sessions` Map with `expiresAt = Date.now() + 24 * 3600 * 1000`. The map is cleared on server restart, effectively invalidating all sessions.  
**Risk:** If the server is not restarted, a stolen token remains valid for 24 hours with no revocation mechanism.

**Remediation (production):**

1. Issue short-lived access tokens (15 min) + long-lived refresh tokens (7 days) signed with RS256.
2. Persist refresh tokens in a database with revocation capability.
3. Implement `/api/auth/refresh` endpoint.

---

## SR-06 — HIGH: No Input Sanitisation Layer

**Finding:** Request bodies are read directly with `req.body` and cast with `as { ... }`. There is no JSON Schema validation or sanitisation middleware.  
**Risk:** Prototype-level: unexpected field types cause runtime crashes (e.g., passing a number for `phone`). Production-level: prototype code should use `zod` or `express-validator`.

**Remediation:**

```typescript
import { z } from 'zod';

const SOSSchema = z.object({
  lat: z.number().min(-90).max(90),
  lon: z.number().min(-180).max(180),
  phone: z.string().regex(/^\+91[0-9]{10}$/),
});

router.post('/sos', (req, res) => {
  const parsed = SOSSchema.safeParse(req.body);
  if (!parsed.success) { res.status(400).json(parsed.error); return; }
  // ...
});
```

## SR-07 — MEDIUM: Hardcoded Admin Credential

**Finding:** Admin login in `server/src/auth.ts` line 108 compares plain-text strings:
```typescript
if (email === 'admin@sahaay.gov.in' && pass === 'SaHaayAdmin2026!') {
```
**Risk:** Credential is visible in source code. Anyone with repo access can log in to the admin portal.

**Remediation (production):**

1. Move credential to environment variable: `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH`.
2. Hash with `bcrypt` (cost factor 12): `bcrypt.compare(pass, process.env.ADMIN_PASSWORD_HASH)`.
3. In `.env.example`, document the variable without the real value.

---

## SR-08 — MEDIUM: In-Memory Session Store

**Finding:** All sessions are stored in a JavaScript `Map` in `server/src/auth.ts`. Sessions are lost on server restart.  
**Risk:** Any server restart (crash, deployment) logs out all users immediately. For a dispatch system, this could strand active missions.

**Remediation:** Use Redis (`ioredis`) or a lightweight SQLite session store.

## Verified Security Controls (Currently Working)

### ✅ Driver Verification Gate

Unverified drivers (those in `PENDING` or `REJECTED` state) receive **HTTP 403 Forbidden** when attempting to toggle duty. Verified by e2e journey test (Journey C).

```typescript
// server/src/routes.ts:151
if (isOnDuty && !driver.isVerified) {
  res.status(403).json({ error: 'Account pending admin verification. Cannot go on duty.' });
  return;
}
```

### ✅ Mission Ownership Enforcement

The `acceptMission` function in `server/src/dispatch.ts` checks that the accepting driver ID matches the dispatched offer. Drivers cannot accept missions intended for other drivers.

### ✅ Admin-Only Routes Protected

Routes under `/api/admin/*` check for a valid `Authorization: Bearer <token>` header where the token's associated role is `admin`. Non-admin tokens receive **HTTP 401 Unauthorized**.

```typescript
// server/src/routes.ts — verifyAdmin middleware
const session = sessions.get(token);
if (!session || session.role !== 'admin') {
  res.status(401).json({ error: 'Admin authentication required' });
  return;
}
```

### ✅ Tamper-Evident Audit Log

All dispatch events are appended to a SHA-256 hash chain (`server/src/audit.ts`). Any post-hoc modification to a log entry invalidates the chain from that point forward. The `/audit/verify` endpoint validates the entire chain.

### ✅ No Real Secrets in `.env`

The `.env` file is listed in `.gitignore` and has never been committed. Only `.env.example` (with placeholder values) is tracked.

### ✅ APK Manifest Permissions

Both Android APKs declare only the minimum required permissions in their `AndroidManifest.xml`:
- `INTERNET` — backend communication
- `VIBRATE` — emergency haptic feedback
- `ACCESS_FINE_LOCATION` — (declared, currently SIMULATED)
- No `READ_SMS`, `SEND_SMS`, `CAMERA`, `CONTACTS`, `CALL_PHONE` — none required.
